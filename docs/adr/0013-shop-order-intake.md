# Shop-Bestelleingang: Shopify-API zuerst, Etsy über Mail

Etwa halb Shopify / halb Etsy, Ziel ~20–30 Aufträge/Woche, keine dauerhafte Schnellerfassung. Etsy-CSV scheidet aus (Export erst zwei Wochen nach Bestelldatum). Etsy-API ist beantragt, kann Wochen dauern oder abgelehnt werden. Deshalb zuerst Shopify-Admin-API; Etsy-Brücke: weitergeleitete Bestellmails ins Spezial-Postfach, IMAP-Warteschlange + Gemini-Parse auf Knopf (ADR `0018`). Shopify-API: nur bezahlte, noch nicht vollständig erfüllte Aufträge; alle Positionen eindeutig gematcht → **offen** plus Todos, sonst **zur Prüfung**. Etsy-Mail: anfangs immer **zur Prüfung**; später dieselbe Match-Regel. Duplikat gleiche Herkunft + Nummer: nicht erneut anlegen. Manuelle Bestellung mit derselben Nummer (selten): Herkunft **Shopify**, Positionen unverändert. Abruf nur auf Knopfdruck (**Shopify abrufen**) mit **Client-Credentials** aus dem Dev Dashboard (Client-ID + Secret → 24h-Access-Token; kein periodischer Hintergrund-Poll, keine Shopify-Webhooks). Abruf ohne Scope `read_customers`; Kundenname aus vorhandenem Kundenfeld oder **Lieferadresse**. Dieser Schnitt nur Anlegen (Nummer, Positionen, Herkunft); **Versendet** bleibt manuell, Fulfillment-Sync später. App-weiter Assistent und Set-Zusammenstellen sind nicht dieser Schnitt.
